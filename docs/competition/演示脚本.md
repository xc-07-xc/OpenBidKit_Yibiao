# 赛道一 · 现场演示脚本

> 目标：8 分钟内让评委看到「不是一键生成，而是一条可管控的标书生产线」，并留下可复核的证据。
> 原则：**成品与证据先讲，实跑只演前 1–2 分钟**。整条流水线真实跑一轮约 13 分钟，不适合现场等。

## 0. 会前 30 分钟清单

| # | 事项 | 判定标准 |
|---|---|---|
| 1 | 设置 → 文本模型 → 测试 | 返回内容，不是超时/401 |
| 2 | 设置 → 智能体配置 → 自检 | 「自检通过」 |
| 3 | 打开「多 Agent 流水线」 | 页头显示 **LangGraph 编排** |
| 4 | 预跑一轮完整流水线 | 6 阶段 success、4 闸门 approved、至少 1 轮返工 |
| 5 | 导出 Word | 文件能打开、目录/正文正常 |
| 6 | 打开知识库「流水线产物」 | 6 个阶段文档都在 |
| 7 | 运行 `npm run inspect:pipeline` | 截图或存文本，确认 4 项检查 |
| 8 | 备份数据库 | 关闭应用后复制 `%APPDATA%\yibiao-client\workspace\yibiao.sqlite` |
| 9 | 准备一份 5–10 页短招标文件 | 现场实跑用，避免等 10 分钟 |
| 10 | 录屏备份完整流程 | 现场模型抽风时直接放录像 |
| 11 | 清理环境 | 关掉占用 5173 的旧进程、通知、无关窗口 |

## 1. 分镜（8 分钟）

### 0:00–0:40 开场：问题

口播：

> 一份标书十万字，资格错一项就废标；请人代写几百到几千，付费 AI 按份收费。我们做的是把这条手工生产线自动化，并且让每一步**可验证、可追溯、可返工**。

画面：标书成品 Word 的第一页 + 一张废标条款截图（可选）。

### 0:40–1:30 全景：它不只是“生成”

操作：侧边栏快速划过「投标文件 / 知识库 / 查重 / 废标项 / 暗标 / 多 Agent 流水线」。

口播：

> 解析、目录、正文、配图、查重、废标、暗标检查都在这里；今天重点讲中间这条多 Agent 流水线，因为它是把“生成”变成“生产线”的地方。

### 1:30–3:00 预跑结果走查（核心）

操作：打开「多 Agent 流水线」，停在预跑完成的那一轮。

依次指：

1. 页头：**LangGraph 编排** + 运行 ID；
2. Agent 团队契约卡片：7 个角色的工具、输入、输出、依赖；
3. 阶段卡：6 个阶段状态、耗时、最近日志；
4. 指标区：阶段通过率、一致性评分、**自动返工轮次（含评分轨迹）**；
5. 展开某个阶段的「查看阶段产物」：结构化 JSON，不是一段散文。

口播：

> 每个阶段是独立 Agent、独立工作区、独立工具白名单；法规阶段是唯一能联网的角色。阶段之间靠黑板传结构化产物，不靠聊天记录。

### 3:00–3:40 交付物与沉淀

操作：

1. 打开知识库「流水线产物」：6 份文档，说明“越跑越厚”；
2. 打开导出的 Word：目录、章节、正文；
3. 指指标区的“质检未通过/评分”提示：导出会提示仅作草稿。

口播：

> 产物同时落工作区和知识库；下一份标书可以直接复用这次的资格结论和技术方案。

### 3:40–4:20 证据页

操作：终端运行

```powershell
cd C:\Users\C\Desktop\OpenBidKit_Yibiao\OpenBidKit_Yibiao\client
npm run inspect:pipeline
```

口播：

> 这不是我口头说的：脚本直接读 SQLite 黑板，核对 4 个闸门、1 次人工打回、返工轮次和评分，全部可复核。

### 4:20–5:40 现场实跑（只演开头）

操作：

1. 上传准备好的短招标文件；
2. 启动流水线；
3. 看解析阶段实时日志滚动；
4. 到解析闸门时，**先打回一次**（填写“缺少类似业绩证明，请复核”），展示产物清空与重跑；
5. 再通过，停在这里。

口播：

> 打回不是撤销，是把这一阶段的产物作废、重新执行；后面每个闸门都是同一套机制。为了不让你等十分钟，剩下的阶段用刚才的预跑结果和录屏补充。

> ⚠️ 注意：启动新流水线会清空黑板里的上一轮阶段数据。所以**先走查预跑结果，再启动实跑**；Word 和知识库产物不会丢。

### 5:40–7:00 平台能力讲解

画面：`docs/competition/技术方案.md` 的架构图 / 或口头讲。

要点（各 20 秒）：

- **图编排**：LangGraph，并行扇出、条件回边、`interrupt()` 闸门、run_id 隔离；
- **执行解耦**：Python 只编排，业务跑在 Node，复用了已有的 Word/知识库/联网能力；
- **验证**：每阶段 JSON Schema + 一致性评分分级 + 人工闸门；
- **自循环**：质检不过 → 回传问题与上一轮成稿 → 只改受影响章节 → 上限 2 轮转人工；
- **可交付**：sidecar 打包进安装包，装完即用，不依赖用户装 Python。

### 7:00–8:00 边界与收尾

口播：

> 当前知识库还是关键词检索，Agent/工作流定义还没做成可视化注册表，调度是固定并行组——这些是我们下一阶段要补的。但它已经不是“一键生成”，而是一条能停下来让人拍板、能自己发现错误并返工、能被脚本复核的生产线。

收尾一句：

> 标书是第一个负载；这套 Harness 同样的结构可以迁到可研报告、方案书、申报材料。

## 2. 五个高光时刻（评委记住的就是这些）

1. **打回重跑**：产物被清空、阶段重新执行，证明“人真的能拦住 AI”。
2. **评分轨迹**：指标区显示“质检分 62 → 88”，证明返工不是安慰剂。
3. **产物 JSON**：结构化字段，证明不是把文章丢给 Word。
4. **知识库回写**：产物进了「流水线产物」，证明越用越快。
5. **inspect 输出**：终端四项检查全绿，证明可复核。

## 3. 失败预案

| 现场情况 | 处理 |
|---|---|
| 返工没触发 | 不硬等：讲“返工由质检判定”，用预跑记录/录屏展示；强调人工打回是同一套闭环 |
| 模型很慢 | 停在解析阶段讲设计，切到预跑结果继续；不要现场等 5 分钟 |
| 联网检索失败 | 说明法规阶段会降级为空来源，不阻塞流程，展示日志即可 |
| Python 服务没起来 | 页头会显示「内置编排」；口头说明回退机制，切到预跑录屏 |
| 应用崩溃 | 重启后阶段会变“阻塞”，这是设计；直接放录屏 |
| 评委要求“你现在跑完” | 用短招标文件 + 快模型，提前说明约 5–8 分钟；或放录屏并同步讲解 |

## 4. 评委可能追问（准备好答案）

| 问题 | 答法 |
|---|---|
| 这不就是 AI 写标书吗？ | 应用是第一个负载；平台层是 Agent 团队、图编排、闸门、验证、返工，标书只是验证场景 |
| 和 LobeHub / DeepSeek Harness 差在哪？ | 它们强在通用工具生态；我们强在强约束任务的验证闭环和领域工具（Word、暗标、查重） |
| 知识库是 RAG 吗？ | 现在是条目化 + 关键词检索，正在补 FTS/向量；重点是“条目化 + 产物回写”的闭环 |
| 返工会不会死循环？ | 上限 2 轮，超限转人工；材料缺失类不返工，避免编造 |
| 换模型还能跑吗？ | 任意 OpenAI 兼容接口，设置里换；Agent 侧不绑定模型 |
| 成本多少？ | 单份标书 token 可从统计看；README 实测 11 万字约 1 元（按当时模型价） |
| 能规模复制吗？ | 可研报告已复用同一套任务框架；下一步把 Agent/工作流做成注册表 |
| 数据安全？ | 默认本地，文件不上传；只有你配置的模型/解析服务会收到必要内容 |

## 5. 5 分钟精简版

砍掉「0:40–1:30 全景」和「5:40–7:00 平台讲解」，只保留：

1. 30 秒问题；
2. 预跑结果走查（1 分钟）；
3. 知识库 + Word（40 秒）；
4. inspect 证据（30 秒）；
5. 现场启动 + 打回一次（1 分 30 秒）；
6. 30 秒收尾。
